# DCB Event Store

Ruby gem implementing the Dynamic Consistency Boundary (DCB) pattern with PostgreSQL and SQLite backends.

## Stack
- Ruby >= 3.3; `pg` and `sqlite3` are optional (dev) dependencies - an application adds the driver for the backend it uses
- Minitest for tests
- SimpleCov for coverage
- Mutant (`mutant-minitest`) for mutation testing

## Project structure
- `lib/dcb_event_store/` - core classes
- `lib/dcb_event_store/sql_store/` - collaborators shared by SQL backends (`SqlBuilder`, `RowMapper`, `Timestamp`)
- `lib/dcb_event_store/postgres_store/` - PG-only collaborators (`Schema`, `Dialect`, `ArrayCodec`, `LockKeys`)
- `lib/dcb_event_store/sqlite_store/` - SQLite-only collaborators (`Schema`, `Dialect`)
- `test/unit/` - unit tests
- `test/integration/` - integration tests (require live PG); backend-neutral cases live in the shared contracts, so these files keep only PG specifics (append-only triggers, LISTEN/NOTIFY subscribe, `text[]` round trip, `test_schema_upgrade.rb`: `create!` adding `tx_id` to a pre-0.6 table, and moving the offset past rows restored from a cluster ahead) plus the PG contract runners
- `test/sqlite/` - SQLite backend tests, no server needed: `test_sqlite_store.rb` (contract runner plus transaction and JSON-encoding specifics), `test_schema.rb` (DDL, append-only triggers, `configure!` pragmas, `:memory:` smoke test), `test_subscribe.rb` (polling subscribe, ported from the PG file) and `test_concurrent_append.rb` (racing connections on one file database)
- `test/concurrency/` - concurrency tests (PG): `test_concurrent_append.rb` races whole appends, `test_in_flight_append.rb` pins one open mid-transaction, `test_out_of_order_commit.rb` (issues #54/#55) checks a subscriber and a snapshot do not step past one; the paused-append helper is `test/support/in_flight_append.rb` (`InFlightAppendHelper`)
- Snapshot tests: `test/support/snapshot_store_contract.rb` (the snapshot store interface, run by `test/unit/test_in_memory_snapshot_store.rb`, `test/sqlite/test_sqlite_snapshot_store.rb`, `test/integration/test_postgres_snapshot_store.rb`) and `test/support/snapshot_decision_model_contract.rb` (`DecisionModel.build(snapshots:)` on every backend, included by the three DecisionModelContract runners, which define `build_snapshot_store`); `test/unit/test_snapshot.rb`, `test_snapshot_instrumentation.rb`, `test_query_key_collisions.rb` (regression: `Query#to_s` is not a safe cache key)
- `test/support/` - shared test infra: `postgres_database.rb` (`PostgresDatabaseHelper`: connection, schema, `build_store`), `sqlite_database.rb` (`SqliteDatabaseHelper`: tempfile database, schema, `build_store`, extra connections) and the backend contracts `store_contract.rb` (append/read/read_from/pagination/instrumentation), `special_characters_contract.rb`, `client_contract.rb`, `decision_model_contract.rb`, `upcaster_contract.rb`, `import_export_contract.rb` (`Store#import` + `EventFile` round trips), plus `in_memory_equivalence_contract.rb` (same scripted operations on the backend and on InMemoryStore, results compared). Each contract is a module run against every backend: PG via `test/integration/`, SQLite via `test/sqlite/test_sqlite_store.rb`, InMemory via `test/unit/test_in_memory_store.rb`. Including classes set `@store` in setup and define `build_store(upcaster: nil)`
- `bench/k6/` - adapter for the dcb.events k6 suite (issue #50), outside the gem runtime: `server.rb` (Puma app, `GET /read` / `POST /append` of the suite's `http_default.js` protocol mapped onto the public store API; backend from `DCB_BACKEND` via `examples/support/backend.rb`, `PUMA_WORKERS` default one per core since one process is GVL-bound), `run.sh` (fetches the suite at a pinned commit into `bench/k6/.suite`, one fresh server per backend/test, exports to `bench/k6/results/`), `summarize.rb` (markdown table, non-zero exit on a failed check/request or a rejected unrelated append). Puma is in the optional `:bench` Gemfile group. `.github/workflows/k6.yml` runs it on `workflow_dispatch` only
- `examples/` - usage examples; `examples/support/backend.rb` builds the store from `DCB_BACKEND` (`postgres` default, `sqlite`, `memory`), so every example runs on any backend. `performance.rb` benchmarks queries and appends, `decode_performance.rb` the cost of turning rows back into events; results in `examples/BENCHMARK.md`

## Database
- PostgreSQL DB: `dcb_event_store_test`
- Setup: `ruby -Ilib -rpg -e "require 'dcb_event_store'; DcbEventStore::PostgresStore::Schema.create!(PG.connect(dbname: 'dcb_event_store_test'))"`
- SQLite needs no setup: the tests create a throwaway database file per test (`SqliteDatabaseHelper`), and `SqliteStore::Schema.create!(db)` installs the schema and the connection pragmas

## Running tests
```sh
bundle exec rake test          # all tests
bundle exec ruby test/integration/test_client.rb  # single file (needs PG)
bundle exec ruby test/sqlite/test_sqlite_store.rb # single file (no server)
# unit + SQLite tiers only, proving they need no PostgreSQL (what CI runs first):
bundle exec ruby -Itest -e 'Dir["test/{unit,sqlite}/**/test_*.rb"].each { |f| require File.expand_path(f) }'
bundle exec mutant run                            # mutation testing (all subjects)
bundle exec mutant run 'DcbEventStore::SqlStore#append'  # single method
```

## Releasing
- `DcbEventStore::VERSION` (`lib/dcb_event_store/version.rb`) is the only place a version is written; the gemspec reads it
- Bumping it on `main` fires `.github/workflows/release.yml`, which tags that commit (bare number, no `v`) and cuts a GitHub release with generated notes. A `.github/release-notes/<version>.md` file, if present, is put ahead of the generated notes (breaking changes go there). Idempotent, and `workflow_dispatch` tags a version that reached `main` before the workflow existed

```sh
bundle exec ruby examples/course_subscriptions.rb              # postgres (default)
DCB_BACKEND=sqlite bundle exec ruby examples/course_subscriptions.rb

```

## Key architecture
- `Event` / `SequencedEvent` - domain event wrappers
- `Query` / `QueryItem` - event stream filtering; a `QueryItem` must name at least one type or tag (`ArgumentError` otherwise), types and tags are deduplicated, as are an `Event`'s tags. `append` of no events raises `ArgumentError` (spec: events must not be empty; issue #53)
- Idempotent append (issue #49), same on all three stores: every event id already stored -> returns the stored `SequencedEvent`s (log order, upcast like a read) without checking the condition, so a conditional retry succeeds; ids only, payload not compared. Some ids stored -> `DuplicateEvent` (`#ids` = the stored ones), nothing written. `SqlStore#append` only looks ids up (`fetch_by_ids` hook, `SqlBuilder#by_ids_sql`, `Dialect#id_in`) when nothing was written (`#replay`: stored ids, else `ConditionNotMet`), so PG keeps its one-statement CTE; a partial write raises and rolls back (`#reject_partial_duplicates!`). `append.dcb` of a replay carries `replayed: true`, `appended_count: 0`
- `AppendCondition` - consistency boundary
- `Namespace` (`lib/dcb_event_store/namespace.rb`, eager, pure) - several bounded contexts in one database, each with its own log. A validated name (`/\A[a-z][a-z0-9_]*\z/`, max 34 chars so the events table's `<name>_events_sequence_position_seq` fits PG's 63 bytes; `sqlite` and `sqlite_*` refused on every backend since SQLite reserves that table prefix) prefixes every object: `events_table`, `event_tags_table`, `snapshots_table`, `channel` (NOTIFY) and `lock_offset` (`crc32(name) & 0x7fffffff << 32`, added to every advisory-lock key so namespaces do not serialize against each other; tag keys keep the low 32 bits; computed once at construction, 0 is the default's alone so a name hashing to 0 takes 1, and a name landing on an offset another already holds publishes `namespace_collision.dcb` once through `DcbEventStore.instrumentation`: over-serializes, never misses a conflict). `Namespace::DEFAULT` (nil name) prefixes nothing and has offset 0, so existing databases read as before. Taken as `namespace:` by `PostgresStore`, `SqliteStore`, `InMemoryStore` and `InMemorySnapshotStore` (validated, otherwise inert; all stores and snapshot stores expose `#namespace`), both `Schema.create!`/`drop!` (`create_sql(ns)`/`drop_sql(ns)` build the DDL, `CREATE_SQL`/`DROP_SQL` remain as deprecated default-namespace constants; PG's `create_sql` opens with `pg_advisory_xact_lock(int, int)` so installs racing at boot queue up; its two functions are shared across namespaces, the trigger message names the table via `TG_TABLE_NAME`; SQLite trigger names carry the table name since they are database-wide), both SQL snapshot stores, `SqlBuilder` and both `Dialect`s (`Namespace.wrap` accepts a name or a Namespace). Every `append.dcb`/`read.dcb`/`subscribe.dcb` payload carries `namespace:` (`StoreInstrumentation#store_identity`, the name or nil) and `snapshot.dcb` the snapshot store's (`Snapshotting.identity`, nil when the store has no `namespace`); `AppsignalSubscriber` tags with it when non-nil, the log subscribers drop nil values so default-namespace lines are unchanged. Tests: `test/unit/test_namespace.rb`, `test/support/namespace_contract.rb` (isolation of reads, sequences, conditions, event ids, snapshots) run by `test/sqlite/test_namespace.rb` (tables/triggers per namespace, polling subscriber reads only its own) and `test/integration/test_namespace.rb` (tables/indexes, trigger message, subscriber on its own channel is not woken by another namespace), plus the cross-namespace lock case in `test/concurrency/test_in_flight_append.rb`
- `SqlStore` - abstract base for SQL backends: instrumentation, paginated read, `last_position`, append orchestration, subscribe loop (listens before catching up, so no commit falls between the two), `settled(checks)` (`SettleCheck(query, after, through, count)`, `lib/dcb_event_store/settle_check.rb`; `settled?` is the one-check form); subclasses implement the hooks (`with_write_transaction`, `acquire_locks!`, `count_matching`, `count_between`, `insert_event`, `fetch_batch`, `max_position`, `notify_appended`, `listen`/`unlisten`/`wait_for_append`) and may override the subscription cursor (`subscription_cursor`/`deliver_new`, a position by default)
- `PostgresStore` - low-level PG operations (advisory locks, single-statement conditional append via CTE, LISTEN/NOTIFY). `LockKeys.for(events, condition)`: every append takes key 0 shared plus one exclusive crc32 key per tag its events carry or its condition names; a condition naming no tag (type-only item or `Query.all`) takes key 0 exclusive instead. Covers both directions of a writer/condition race on one tag (issue #42; `test/concurrency/test_in_flight_append.rb` holds an append open mid-transaction and checks the racing one blocks). Positions are taken at INSERT and visible at COMMIT, so appends on disjoint tags commit out of position order; two consequences are handled here. `subscribe` (issue #54): every row stores `tx_id BIGINT DEFAULT pg_current_xact_id()::text::bigint + <ns>_events_tx_offset()` (PG >= 13; the offset is a per-namespace STABLE SQL function, `Namespace#tx_offset_function`, created at 0; `Schema.create!` adds the column to an older table with `ADD COLUMN IF NOT EXISTS` (fast default, no rewrite), index `(tx_id, sequence_position)`, and `rebase_tx_offset_sql` raises the offset when the table holds a tx_id past this cluster's counter, i.e. after a dump/restore). The cursor is `[tx_id, position]`; `SqlBuilder#commit_order_sql` reads that order filtered by `Dialect#settled_clause` (`tx_id < pg_snapshot_xmin(...) + offset`), then `pending_sql` probes for a matching row left past the cursor (`@held_back`, so `wait_for_append` polls `HELD_BACK_POLL`, since the blocker may not NOTIFY; it also drains queued NOTIFYs); `after:` resolves to the tx_id of the row at or below it. `settled(checks)` (issue #55): one transaction with `SET LOCAL lock_timeout` (`SETTLE_LOCK_TIMEOUT`, 50ms), each check in a savepoint: take what `LockKeys.for([], condition on query)` names (global key in its mode, tag keys shared; `advisory_keys` shared with `acquire_locks!`), then `count_between` in a later statement must equal `count`; `PG::LockNotAvailable` = false; the savepoint rollback releases the locks. Was named `Store`; `store.rb` keeps `Store`, `Schema` and `PgArrayCodec` as aliases marked with `deprecate_constant` (covered by `test/unit/test_deprecated_aliases.rb`)
- `SqliteStore` - low-level SQLite operations: appends run in `BEGIN IMMEDIATE` (single writer database-wide, so the consistency check needs no extra locking), tags are indexed in a separate `event_tags(tag, sequence_position)` table standing in for PG's GIN index, and `subscribe` polls instead of using LISTEN/NOTIFY: `wait_for_append` sleeps `poll_interval:` (default 0.1s) until either `PRAGMA data_version` moved (another connection committed) or the connection's own `total_changes` moved (a store that appends and subscribes over one connection), then the shared loop reads from the last delivered position. A subscriber normally holds its own connection on the same file; `:memory:` cannot be shared. `Schema.configure!` sets WAL and a GVL-releasing busy handler (`busy_handler_timeout=`), without which a thread waiting for the write lock would starve the thread holding it
- Backend classes (`SqlStore`, `PostgresStore`, `SqliteStore`, the deprecated `Store` aliases) are `autoload`ed from `lib/dcb_event_store.rb` and load on first reference, each backend file requiring its own collaborators; `InMemoryStore` and the rest stay eager. Mutant needs them loaded to see them as subjects, hence the extra `requires` in `.mutant.yml`
- `created_at` decoding - the only timestamp the gem parses, once per row, and formerly the bulk of a decoded row (~11us of ~17.6us). Now driver-native on both backends: PG installs a `TIMESTAMPTZ` result type map on its connection (`PostgresStore.result_type_map`) so the driver builds the Time in C, and SQLite stores epoch microseconds in an `INTEGER` column that needs no parsing. `Dialect#decode_timestamp` picks the shape apart per backend and falls back to `SqlStore::Timestamp`, which reads the fixed text shape by byte offset (~2us), which in turn falls back to `Time.parse` for anything else -- so a database written before either change still reads. Times returned match `Time.parse` exactly (UTC for `Z`, a fixed offset otherwise). Measured in `examples/BENCHMARK.md`; `examples/decode_performance.rb` reproduces it
- **A connection belongs to the store it is given to** - `PostgresStore` replaces its result type map, holds LISTEN/advisory locks/transactions on it; `SqliteStore` depends on its pragmas. Application queries need their own connection
- `<Backend>Store::Dialect` - per-backend SQL details injected into `SqlBuilder`/`RowMapper` (placeholders, type/tag matching, insert casts, tag list encoding); `PostgresStore::Dialect` encodes lists through `PostgresStore::ArrayCodec` (was `PgArrayCodec`, kept as an alias)
- `InMemoryStore` - single-threaded drop-in for either SQL store, for fast tests without a database (runs the same shared contracts: `test/support/*_contract.rb`); reads scan the whole log and `subscribe` never blocks
- `Client` - high-level API (append, read, subscribe)
- `Projection` / `DecisionModel` - higher-level abstractions. `DecisionModel.build(store, snapshots: snapshot_store, **projections)` takes `store.last_position` first and drops everything past it from the reads (so an event landing between two reads is neither folded nor guarded), reads one group per snapshot position (projections without a snapshot form the nil group), merges the reads by position, folds each projection from its snapshot state (`Projection#fold(events, from:)`), guards the condition at the highest position any group's read covered (its last event, or its snapshot position when it read nothing; never the head, which on PG can lie past an in-flight same-tag append) and writes each group's snapshots at its own coverage once that is `Snapshot#every` positions past them and the event store's `settled` agrees (one batched call) (skipped for a store without it; also skipped when the projection folded an event past its coverage) (`DecisionModel::Snapshotting`)
- `Snapshot` - per-projection snapshot config (`name`, `version` (required, no default: invalidation is explicit), `every`, `dump`/`load`); key = `"[epoch/][namespace/]name/vN/#{query.fingerprint}"` (namespace = the event store's, passed by `DecisionModel.build`, so two logs sharing one snapshot table never share a key; the stores' `purge` uses their own namespace), the fingerprint swapped for its SHA-256 hex when longer than 64 chars (`Query#fingerprint` is JSON of the items; `Query#to_s` is for logs and not collision-free), `DcbEventStore::Snapshots.epoch` a process-wide prefix that invalidates everything at once. `Snapshot.key_prefix(name, version, namespace:)` / `.epoch_prefix` are what the stores' `purge(name:, keep_version:)` / `purge_other_epochs` match on (substr, not LIKE: SQLite's LIKE is case-insensitive). `Snapshots::InMemorySnapshotStore` / `PostgresSnapshotStore` / `SqliteSnapshotStore` (`lib/dcb_event_store/snapshots/`) share one interface (`fetch`, `fetch_many`, `store` with a forward-only upsert, `delete`, `clear`, `purge`, `purge_other_epochs`); the SQL ones use the `projection_snapshots` table that `<Backend>Store::Schema.create!` installs with the events schema (mutable, no append-only trigger). Contract: `test/support/snapshot_store_contract.rb`, `test/support/snapshot_decision_model_contract.rb`
- `SqliteStore::Dialect#tags_contain(params, tags, after:)` repeats the position bound inside the `event_tags` subquery, so a catch-up read after a snapshot scans only the tag's rows past it (`PostgresStore::Dialect` accepts `after:` and ignores it). `examples/snapshot_benchmark.rb` + `examples/SNAPSHOTS.md` measure snapshots against replay (an in-process materialized-stream cache was measured too and dropped)
- `Upcaster` - event schema migration on read
- `Web` - optional, read-only event browser. Framework-agnostic Rack app (`DcbEventStore::Web`, `require "dcb_event_store/web"` - NOT auto-loaded, adds no runtime dep) mountable in Rails/Sinatra/bare Rack. `ReadModel` (PG glue: count/head/newest-first paging/find, reusing `SqlStore::SqlBuilder` + `RowMapper` with `PostgresStore::Dialect`), `Router` (route dispatch), `ListParams` (pure paging + Query building - the mutation-tested part), `View` (ERB rendering, `web/views/*.erb`). Connection via `Web.connection = <pg conn or callable>`, or auto-borrows ActiveRecord's. Routes: `GET /` (list + type/tag filter + paging), `GET /events/:position` (detail), `GET /snapshots` (list, `?q=` key substring, paging, lag behind head), `GET /snapshot?key=` (state JSON). Every route reads one namespace, chosen by `?ns=` (absent = default, or the first offered when the default is not); `Web.namespaces = [nil, "billing"]` pins the list, else `ReadModel.namespaces(conn)` discovers `events`/`<name>_events` tables with the event columns on each request; unknown ns is a 404. `ReadModel.new(conn, namespace:)` reads that namespace's events and `projection_snapshots` tables; the `Router` takes a `namespace -> ReadModel` callable plus the list. `ListParams#namespace(available)` is the pure ns resolution (mutation-tested).
- `EventFile` - JSON Lines import/export for seeding/backup/backend copies (`export(store, io_or_path, query:, after:)`, `import(store, io_or_path, batch_size: 1000)` -> `ImportResult(read, imported, skipped)`, `encode`/`decode`/`each_event`). Exports start with a header line (`{"format":"dcb_event_store/events","version":1,exported_at,gem_version,store,query,after,description}`, `EventFile::Header`, `EventFile.header(src)`, `ImportResult#header`); optional on import, first line only, format/version checked, unknown header keys ignored. Only `type` required per event line; unknown keys raise. Import goes through `store.import(sequenced_events)` (all three stores): keeps id/created_at/schema_version, fresh positions in order, skips stored ids, no condition; `SqlStore` hooks `lock_for_import!` (PG: key 0 exclusive) + `import_event`, dialects `import_sql`/`import_params`/`encode_timestamp`. `DcbEventStore::CLI` (`lib/dcb_event_store/cli.rb`, not loaded by the gem) backs `bin/dcb_events export|import`. Tests: `test/support/import_export_contract.rb` (all backends), `test/unit/test_event_file.rb`, `test/sqlite/test_cli.rb`
- `Notifications` / `StoreInstrumentation` / `LogSubscriber` / `RailsLogSubscriber` - observability: pub/sub instrumentation events (`append.dcb`, `read.dcb`, `subscribe.dcb`, `projection.dcb`, `decision_model.dcb`, `snapshot.dcb` from `DecisionModel::Snapshotting` around snapshot loads/writes; tested in `test/unit/test_snapshot_instrumentation.rb`) published through the global `DcbEventStore.instrumentation`; `subscribe.dcb` carries delivery lag, per-event or batched via `subscribe_instrumentation:` store option. `LogSubscriber` is a plain-logger adapter; `RailsLogSubscriber` renders events in ActiveRecord SQL-query style (no Rails dependency); `ActiveSupportInstrumentation` is a drop-in engine routing events through `ActiveSupport::Notifications` (shared engine contract: `test/support/instrumentation_contract.rb`); `AppsignalSubscriber` maps events to AppSignal custom metrics (lazy require, engine-agnostic). `Railtie` (loaded from `lib/dcb_event_store.rb` only when `Rails::Railtie` is defined, so the gem still carries no Rails dependency) does the Rails wiring at boot without an initializer in the app: swaps in `ActiveSupportInstrumentation` and attaches `RailsLogSubscriber` to `Rails.logger`, configurable through `config.dcb_event_store` (`instrumentation:`, `log:`, `logger:`, `pattern:`, `colorize:`; the attached adapter and its handle come back on the same options object). Tested in `test/unit/test_railtie.rb` against a config double plus subprocess checks that the file loads only inside Rails — which is why `test/unit/test_rails_log_subscriber.rb` saves and restores `::Rails` around its own stubs
